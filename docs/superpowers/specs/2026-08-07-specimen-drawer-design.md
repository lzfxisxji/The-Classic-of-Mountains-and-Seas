# 异兽研究档案抽屉设计说明

## 目标

将现有简单 `dialog` 弹窗升级为右侧滑入的沉浸式异兽研究档案抽屉，使“展开异兽档案”和“调取异兽档案”打开当前选中异兽的完整研究资料。

## 范围与约束

- 不改动经纬铜盘地图的视觉与交互结构。
- 不破坏异兽切换、地图点击、档案卡片选择或环境音。
- 保持原生 HTML、CSS、ES modules，不引入第三方依赖。
- 延续暗色古卷、黑红氛围、鎏金线条、科研观测档案风格。

## 交互

- 复用原生 `<dialog>` 作为抽屉宿主，保留原生遮罩、Esc 关闭和焦点管理。
- 桌面端宽度为 480px，固定右侧；打开时用 380ms `transform` 滑入，遮罩同时淡入。
- 移动端为全屏档案页；减少动态效果偏好下取消滑入与渐变。
- Hero 的“展开异兽档案”和地图的“调取异兽档案”均调用 `openRecord(current)`。
- 抽屉底部相关档案按钮调用既有 `setSpecimen(id)`，随后刷新抽屉内容，保持首页卡片和地图状态同步。

## 内容层级

1. 档案头部：NO.、中文名、拉丁名、关闭按钮。
2. 原画展柜：当前异兽插画、金色框线、档案识别角标。
3. 基础档案：来源、观测区域、风险等级、异能谱系。
4. 研究摘要：每只异兽独立 150–200 字文案，覆盖外貌、神话记载、能力与文化寓意。
5. 古籍摘录：以古卷引文块呈现，不伪装为未经核验的逐字原典。
6. 属性数据：力量、速度、智慧、异能、危险度五项轻量数据条。
7. 相关档案：其他三只异兽的切换按钮。

## 数据与渲染

在每个 `beasts[id]` 条目新增 `research`、`quote` 与 `stats`。`stats` 为包含五个 0–100 数值的对象。`app.js` 通过单一 `renderRecordPanel(beast)` 将所有面板字段写入 DOM；不复制异兽数据至 HTML。

无效 id 不触发面板更新；缺失资料字段显示“档案待补全”，避免异常。所有文本经 `textContent` 写入。

## 验收

- 四个异兽均能从 Hero、地图和相关档案打开或切换面板。
- 抽屉内容、主视觉、卡片活动态和地图节点保持同一异兽。
- Esc、关闭按钮、点击遮罩均可关闭；移动端全屏可滚动。
- `prefers-reduced-motion` 时无强制滑动动画。
- JavaScript 语法通过，既有环境音与弹窗外功能无回归。
